01

CAPABILITY SCOPE

WHAT IT DOES

Optimus Hub bridges Orca's multi-agent runtime with a decentralized repository index. It exposes curated capabilities while enforcing zero-privilege defaults and total execution isolation.

RUNTIME ISOLATION

No ambient authority. Every skill, server and extension operates inside strict capability boundaries with instant rollback.

01.1 // Discover
Browse the marketplace index. Every entry declares its Git source and ref, so each listing is reproducible.
01.2 // Skills
Reusable instruction packs for planning, code review and hand-off between worktrees, installed as versioned content.
01.3 // MCP servers
MCP server entries listed with their origin, ready to connect to your agents without leaving Orca.
01.4 // Installed and updates
Local inventory with the active version, content hash and consent state. Updates are previewed before they are applied, with rollback to the previous version.
01.5 // Collections
Curated groups of skills and related entries that install together for a complete workflow.
01.6 // Settings
Plugin-scoped settings, readable and writable only by the plugin itself, under the settings:own boundary.
02

LIFECYCLE & EXECUTION

HOW IT WORKS

Six deterministic stages take a plugin from a Git index to a typed terminal command. Every stage is enforced by Orca, and the plugin only ever acts inside the boundaries the user approved.

STAGE 01 · INDEX RUN BY: ORCA (HOST)
What happens
Orca resolves the marketplace index from a Git repository. Each entry points to a plugin repository and a pinned ref, so every listing is reproducible.
Run by
Orca (host). The plugin is not installed or running yet at this stage.
Can
Read-only Git resolution of the index and its named refs.
Cannot
Execute or ingest any code. Indexing never activates anything.
Tech fact
Index file: orca-marketplace.json · installs resolve to a pinned Git ref.

03

DEPLOYMENT & DISTRIBUTION

INSTALL

Choose an install method in Orca ADE. Adding as a marketplace source ensures automatic index synchronization and rollback-enabled updates.

1 · Add as a marketplace source RECOMMENDED

AUTO-UPDATES ENABLED

In Orca, open the plugins view and use Manage sources to add this Git URL as a marketplace source. Then install Optimus Hub from the index. Installs added this way receive updates and rollback capabilities.

https://github.com/aikogxstudios/optimus-hub-plugin.git

2 · Direct install

STATIC PINNED REF

Alternatively, install the plugin source directly at the pinned ref. A direct install does not receive updates; to update, repeat the install pointing at a newer ref.

https://github.com/aikogxstudios/optimus-hub-plugin#v0.2.0

04

CAPABILITY MANIFEST

PERMISSIONS

Requested on install and shown verbatim in the consent dialog. Activation requires explicit approval.

Capability What it grants Boundary Constraint
workspace:read Read the name, branch and terminal list of your focused worktree. Read-only access to focused worktree metadata; no raw filesystem browsing.
notifications:show Show desktop notifications labeled with the plugin name. Mandatory [Optimus Hub] prefix to eliminate prompt spoofing.
terminal:send Type text into a terminal the plugin can see — always one specific terminal. Target terminal must be user-selected; cannot spawn unmonitored sessions.
05

ISOLATION BOUNDARY

SANDBOX & SECURITY

▸ ZERO NETWORK ACCESS

The panel runs inside an isolated iframe with CSP connect-src 'none'. No outbound HTTP/HTTPS requests, no WebSockets, and zero external telemetry.

▸ ZERO DISK ACCESS

No filesystem API bindings. Files and directories cannot be read or modified directly. Any data access must pass through Orca ADE's permission-checked host calls.

▸ ISOLATED STORAGE (settings:own)

Settings and active marketplace sources are strictly scoped to the plugin's private namespace. Other extensions cannot inspect or tamper with this configuration.

▸ The panel has no network and no disk access. It runs inside a sandboxed frame and communicates with the host only through the plugin API methods allowed for its session.
